# Architecture analysis

Use this skill to identify architectural concepts and implementation patterns.

## Candidate concepts

Examples include:

- Layered Architecture;
- Hexagonal Architecture;
- Clean Architecture;
- Event-Driven Processing;
- CQRS;
- Saga;
- Repository;
- Factory;
- Strategy;
- Adapter;
- Dependency Injection.

This list is not exhaustive.

## Evidence requirements

Do not infer a pattern solely from:

- class names;
- package names;
- directory names;
- framework conventions.

Use corroborating evidence from code structure, dependencies, configuration,
interfaces, runtime interactions or documentation.

## Reporting

For each pattern include:

- pattern name;
- repository-local or workspace-wide scope;
- supporting evidence;
- contradictory evidence when present;
- confidence;
- unresolved questions.

Clearly distinguish confirmed patterns from likely interpretations.
